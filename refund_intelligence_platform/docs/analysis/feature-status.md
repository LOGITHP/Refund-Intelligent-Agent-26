# Feature Implementation Status & Evidence Matrix

This analysis classifies capabilities in `refund_intelligence_platform` strictly from executable source code, configuration, migrations, deployment manifests, and verified test runs. It uses only the allowed status classifications:

- `Implemented — verified`
- `Implemented — not runtime-verified`
- `Partially implemented`
- `Simulated / mocked`
- `Planned`
- `Not found`

> **Test Verification Context:** `python -m pytest -q` inside `agent_backend/` passed **71 tests** (`tests/unit/`, `tests/integration/`, `tests/agents/`) against in-memory SQLite, FastAPI `TestClient`, mocked external HTTP transports, and `InMemoryObjectStorage`. Live multi-container Docker Compose, PostgreSQL 16 triggers, real PayPal Sandbox credentials, real MinIO buckets, and live NVIDIA NIM API calls were not executed in this verification run (`Implemented — not runtime-verified` where code exists but live external runtime was not exercised). TypeScript compilation (`npx tsc --noEmit`) passed with exit code `0` in `ops_frontend/`.

## Code-vs-Documentation Discrepancies Observed

During repository inspection, the following differences between earlier design/ledger files and the executable code were identified and resolved in favor of executable code:

1. **Database Table Count:** `docs/sdd-ledger.md` records `18` tables from migration `0001_initial_schema.py`. Migration `0002_platform_users.py` and `app/db/models.py` added a **19th table**, `platform_users`.
2. **Configured NVIDIA NIM Models:** `docs/specs/2026-11-12-agentic-refund-platform-design.md` lists `meta/llama-3.3-70b-instruct` and `meta/llama-3.2-90b-vision-instruct`. Actual `app/core/config.py`, `app/agents/llm_factory.py`, `.env.example`, and `docker-compose.yml` default both `NVIDIA_REASONING_MODEL` and `NVIDIA_VISION_MODEL` to **`nvidia/nemotron-3.5-super-vl-120b-a12b`**.
3. **Card Networks & Tracking Prefixes:** `docs/specs/2026-11-12-agentic-refund-platform-design.md` mentions `TRACK-SK-*` and `AMEX`. Executable `simulators/carrier_simulator/app/main.py` generates `TRK-SK-*`, and `simulators/issuer_simulator/app/main.py` + `operations/routes.py` restrict `card_network` strictly to `VISA`, `MASTERCARD`, and `RUPAY`.
4. **Ops Auth Architecture:** Earlier spec drafts reference shared Shipkart roles for Operations. Implementation isolates Operations access behind `platform_users` email/password credentials in `refund_intelligence` DB (with `/operations/auth/demo-session` gated to `development`/`dev`/`local`/`test` environments).
